## البنية داخل الملف الواحد
```
index.html
├── <style>          (~1-640)   كل CSS، متغيرات الألوان navy/gold
├── <body>           (~640-765) شاشة الدخول + الشاشة الرئيسية (3 تبويبات) + أشرطة سفلية ثابتة
```

## دورة عمل المندوب (مؤكَّدة من الكود مباشرة)

1. **تبويب "البحث":** المندوب يكتب رقم الحالة أو يمسحها بالكاميرا (`searchCase()`) → تظهر في قائمة مؤقتة محلية (`fetchedCases`, `Map`) — **لا تغيير في قاعدة البيانات بعد**.
   - (منذ 25 أغسطس 2026) يقدر أيضاً يختار نوع المنتج لهذه الحالة في نفس الشاشة، قبل ما تنتقل للسلة — راجع `04_FEATURES.md`.
2. **زر "📦 خد المحدد للسلة"** (`confirmPickup()`): هنا يحدث `PATCH` فعلي على `cases`:
   ```js
   { status: 'out_for_delivery', current_holder: currentUser.name, picked_up_at: new Date().toISOString() }
   ```
   يُطبَّق على كل صفوف نفس `case_number` (بشرط `current_holder=is.null` لمنع تعارض مندوبَين على نفس الحالة).
3. **تبويب "سلتي":** يعرض حالات `out_for_delivery` الخاصة بالمندوب الحالي فقط (`loadCart()`، يُعاد جلبها من Supabase في كل مرة يُفتَح فيها هذا التبويب — لا حالة محلية دائمة).
   - (منذ 25 أغسطس 2026) البطاقات مجمَّعة بصرياً حسب العيادة، مع دعم تسليم دفعة كاملة بخطوة واحدة — راجع `04_FEATURES.md`.
4. **تسليم فردي:** اختيار منتج + اسم مستلم → إدراج صف واحد في `deliveries` → `PATCH` يُحوّل **كل** صفوف نفس `case_number` لـ`delivered` → إشعار تليجرام.
5. **إرجاع:** سبب اختياري → إدراج في `returns` → الحالة ترجع لـ`ready` (وليس `registered`).

## نقاط حساسة يجب معرفتها قبل أي تعديل
- **ملف واحد بلا أداة بناء** — أي تعديل يُختبَر بفتح الملف مباشرة (عبر خادم HTTP محلي، ليس `file://` مباشرة لأن `localStorage` يُعطَّل على أصل `file://` وهذا التطبيق يعتمد عليه بالكامل للجلسة والتخزين المؤقت).
- **لا تفترض بنية React/Vite** — هذا جافاسكربت خام بالكامل، الدوال تُستدعى مباشرة من مستمعي أحداث DOM.
- **مشاركة قاعدة البيانات مع `mamelon-erp` تعني:** أي هجرة/تعديل مخطط تُنفَّذ من طرف `mamelon-erp` (مثل إضافة عمود لجدول `cases`) تنعكس هنا فوراً — راجع وثائق `mamelon-erp` (`docs/03_DATABASE.md` هناك) قبل افتراض عدم وجود عمود معيّن.
