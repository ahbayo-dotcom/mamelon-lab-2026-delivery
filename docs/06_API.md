# 06. نقاط الاتصال الخارجية (External Integrations)

## Supabase (REST/PostgREST)
- **الاتصال:** نداءات `fetch` مباشرة (بلا SDK) لـ `https://qhhqodxbhhvhkjtzmmsh.supabase.co/rest/v1/...`.
- **المصادقة:** `apikey` + `Authorization: Bearer <anon key>` ثابتَين في الكود — هذا **متعمَّد وآمن** (نفس نمط `mamelon-erp`)؛ مفتاح `anon` مصمَّم أصلاً ليكون علنياً، والحماية الفعلية تأتي من سياسات RLS على مستوى القاعدة، لا من إخفاء المفتاح.
- **الجداول:** راجع `03_DATABASE.md`.

## بوت تليجرام
- **الآلية:** نداء `fetch` مباشر من كود العميل لـ `https://api.telegram.org/bot<TOKEN>/sendMessage` — بلا أي خادم وسيط.
- **الاتجاه:** إرسال فقط (Send-only) — لا استقبال، لا أوامر، لا Webhook.
- **الوجهة:** مجموعة تليجرام واحدة ثابتة (`chat_id` واحد لكل الإشعارات، بلا تمييز بين طبيب/عيادة).

### 🔴 ثغرة أمنية موثَّقة: توكن البوت مكشوف بالكود المصدري
```js
const TELEGRAM_BOT_TOKEN = "8721178342:AAEcfnw2rFvEoVCee_kkdONPEjMRT2fAnnU";
const TELEGRAM_CHAT_ID = "-5306056456";
```
**بخلاف مفتاح Supabase الـ `anon`، هذا سرّ حقيقي.** أي شخص يفتح "عرض المصدر" (`view-source:`) يحصل عليه، ويقدر:
- ينتحل شخصية البوت ويرسل رسائل مزيَّفة تبدو رسمية لنفس المجموعة.
- يستغل أي صلاحيات إضافية للبوت (لو وُجدت) بالكامل.

**التوصية (لم تُنفَّذ بعد، بانتظار قرار المستخدم):**
1. **الأبسط:** قبول المخاطرة الحالية (تطبيق داخلي محدود الاستخدام) + تدوير التوكن دورياً عبر BotFather (`/revoke` أو `/newtoken`).
2. **الأصح تقنياً:** نقل نداء تليجرام لدالة خادم (Supabase Edge Function) بحيث لا يظهر التوكن في كود العميل إطلاقاً.

**لا تُصلَح هذه الثغرة تلقائياً دون طلب صريح من المستخدم** — موثَّقة للعلم والتذكير فقط.
